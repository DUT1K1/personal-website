Starting a new engineering role always resets your standards a bit. You quickly see which habits are solid and which ones only looked solid inside familiar projects.

## What changes in a new environment

At Quantori the biggest early reminder for me has been that clean software is not only about code style. It is about making behavior obvious: naming things well, validating inputs strictly, and leaving enough structure that the next engineer can move fast without guessing.

I also like how Python changes the shape of backend work. The language is compact, but that does not mean the design should be loose. If anything, it pushes me to be more explicit about contracts, tests, and operational behavior because small files can still hide big complexity.

> A concise language still needs explicit engineering discipline.

## Practices I am reinforcing

Right now I am trying to stay disciplined around a few basics:

- write code that is easy to review
- keep functions narrow in purpose
- prefer simple data flow over clever abstractions
- treat tests as part of the feature, not a cleanup task

## Why the first weeks matter

It is still early, but that is exactly why this phase is useful. Early weeks reveal what kind of engineer you are becoming. You do not have the comfort of intuition yet, so your habits are exposed very clearly.

For me, that is a good thing. It forces sharper thinking, better questions, and more honest engineering.
